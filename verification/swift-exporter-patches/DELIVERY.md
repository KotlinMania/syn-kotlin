## Compatibility changes that must travel with delivery

- `KotlinError.wrapped` is removed. Its replacement stores an immutable String captured at the boundary. The `init(wrapped:)` label remains, but code reading or writing the property breaks; original Kotlin object identity and later message mutation are not preserved. This is a source and binary compatibility change.
- Swift resources, generated Native Kotlin runtime, C headers and exporter classes must be delivered coherently. Earlier experimental Flow changes cannot be mixed with independently selected runtime files. The retained legacy entry and new ready/take entry have distinct contracts.
- Generic reverse callbacks involving arbitrary cached non-Sendable Kotlin objects still lack a proven automatic registration/ownership contract. The original 22 cases have not passed. A separate six-case MainActor lexical-frame result requires explicit caller registration and does not prove that old API compatible.
- The tested scope is KGP/Native 2.4.20 and the recorded Swift toolchain. Neither 2.4.21 compatibility nor fleet-wide compatibility follows from it.
- BitFlags exposes another unvalidated producer family: recursive F-bounds cause UpperBoundTypeProjectionRenderer stack exhaustion while emitting explicit Kotlin bridge-call arguments. RECURSIVE_BOUNDS.md records the actual stacktrace and source classification. Component57182 has not been validated against it; do not extend the proposed initial ProcMacro2 scope by implication.

## Native wrapper ownership changes the delivery closure

The actual five-case runtime contract validation in ordinary-runtime/contract-results.json now passes only with a coherent Native source-header correction as well as the exporter runtime correction. Exact official Kotlin2.4.20 KotlinBase.h lacks the retained-return declaration required by its factories' existing owned alloc/init implementations; actual Swift SIL imports autoreleased results. The checked message-helper patch additionally prevents a plain KotlinBase from aborting on a forced Throwable cast.

An isolated exporter coordinate alone cannot supply the Native header. Any delivery plan must account for the matching Native SDK source-header input, exact compiler/Native version, importer ownership semantics and fresh real consumer validation. Preserve original binaries and source/blob provenance; do not silently overwrite installed SDKs or official cache artifacts. This finding does not authorize a custom SDK distribution, component adoption, external submission or publication. The existing proposed coordinate is not a verified production route for this expanded closure.

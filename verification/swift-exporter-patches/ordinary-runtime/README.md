# Ordinary Swift runtime repair

This minimal source patch set targets the actual strict Swift 6 library failure independently of reverse async ownership. Apply it to the exact Kotlin 2.4.20 revision and upstream paths recorded in provenance.json. It changes only the standalone RuntimeSupport Swift resource and the printer's implementation-import spelling. The sibling full investigation patches contain additional async changes and are not required by this proposal.

The RuntimeSupport patch uses internal bridge imports and captures an immutable String diagnostic at construction. Its two redundant cast corrections retain the existing conversion semantics under warnings as errors. The printer patch emits internal imports for generated library/stdlib/dependency bridge modules, without changing function or async declaration printing.

The diagnostic API changes deliberately: the mutable KotlinBase-backed wrapped property is removed; init(wrapped:) captures its message immediately and message exposes the snapshot. Existing code that reads or mutates wrapped needs migration. Do not describe this as binary/source compatibility with the old runtime type. No new compiler coordinate or official release exists here.

Required validation is one coherent producer-component build, followed by the actual ProcMacro2 shared checkout and all three existing Swift cases under actual dependency/client Swift 6, macOS15 and warnings as errors. Preserve all Kotlin/Swift tests and targets. Verify exact generated public declarations and real published ProcMacro 0.1.4 resolution; any coroutine-support removal belongs to its owner and must match actual API use. Test diagnostic message/fallback capture, immutable String-only storage and release of the original Kotlin object. Keep baseline versus corrected output hashes and Native/C API comparison. Stop and classify subsequent enum or bridge diagnostics rather than rewriting generated output or weakening checks.

Current limits: RuntimeSupport is verified in the broader isolated candidate, but this minimal printer/component combination has not been compiled, packaged or injected into ProcMacro2. Product source, installed compiler and published dependencies remain unchanged. An explicit official upstream submission/release or an explicitly authorized immutable producer publication route is required before consumer adoption.

# Historical generated spanned.rs adoption

The adoption record below describes the 2026-10-25 implementation. The current
source correction is described after that record.

Spanned.kt is the complete raw rust-kotlin output after adding this package/header
and running ktfmt. No body is hand-patched. Source: tmp/syn/src/spanned.rs, all five
top-level items, full/derive enabled, zero configured-out items. All 95 source
comment records are retained, including original Rust examples and limitations.
Generator checkpoint: rust-kotlin `0a2affa`.

SpannedBindings.kt is explicitly separate Kotlin call-site dispatch glue. It
selects the generated typed evidence for Span, DelimSpan or a Kotlin ToTokens
implementation. It contains no span algorithm. Its JVM facade is kept as
SpannedKt so the previous public extension signatures remain available to
compiled callers. Expr.span and QSelf's delimiter helper now use generated
adapters directly. Other existing imports continue through the thin bridges.

Two old divergences were reproduced against Rust before adoption: Span.span
returned the mutable original wrapper; and ToTokens.span dispatched through an
overridden owned conversion instead of the borrowed &T forwarding implementation.
The generator uses the existing lossless Span Copy API and the existing Quote
operations through an explicit borrowed forwarding object. Quote sources and
concurrent configuration were not changed.

Verification: 15 focused Rust observations for unchanged generated Kotlin; 204
translator tests; 434 JVM and 432 macOS Syn tests, including four new regressions.
External implementation of the sealed trait and evidence is rejected. Syn 0.4.0
published to local Maven with the normal command, 179 tasks, without disabling
targets. JVM facade inspection confirms the ToTokens and Span overloads and the
new DelimSpan overload. Other platform execution, macro-host name-resolution
hygiene and universal Rust trait/borrow equivalence are not claimed.

The Rust harness keeps QSelf crate-local by wrapping the actual Syn QSelf type;
re-exporting a foreign type would change Rust coherence rules. QSelf's operational
implementation belongs to path.rs and is covered here only by existing port tests,
not represented as generated by spanned.rs.

Full provenance, raw/ordinary diffs, dependency hashes, configuration and bootstrap
receipt are in ../rust-kotlin/docs/syn-emission-20.md and its validation JSON.
Current supported bound representations are Span, DelimSpan and Kotlin ToTokens;
primitive/Option/Box representation coverage is not implied.

## Source correction

Upstream `spanned.rs` declares `Spanned::span`, its blanket implementation, and
private sealing. It has no named implementation adapters or bound-case enum.
The Kotlin file now contains the sealed `Spanned` interface and the existing
span extensions. The generated implementation classes, bound cases, import
alias, and separate binding file have been removed. Its comments describe the
upstream behavior using Kotlin names and prose.

Kotlin extensions express the blanket implementation for the existing
`ToTokens`, `Span`, and `DelimSpan` representations. The anonymous `ToTokens`
implementation preserves the borrowed dispatch from Quote's `ToTokens for &T`:
only `toTokens` is forwarded, so receiver overrides of `toTokenStream` and
`intoTokenStream` cannot replace the borrowed conversion. Span results retain
their independent value semantics. `Expr.span` retains its concrete signature,
and `QSelf.span` calls its upstream `QSelfDelimiters` representation directly.

The three extension signatures still use the natural `SpannedKt` JVM facade.
Removing the synthetic classes is a Kotlin API change: direct callers must
use the public span operations. No upstream public Rust type is removed.
The four existing regression tests now use only those public operations and
retain checks for borrowed dispatch, span copies, delimiter joining, empty
streams, and the cross-source fallback. Historical test counts above do not
validate this correction.
